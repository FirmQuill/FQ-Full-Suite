# FirmQuill Full Suite: team collaboration

1. Run the Full Suite host, sign in as owner and select your company. **Collaboration groups** manages that company's membership. A user sees group messages and drives only while a member. Being the company owner does not give automatic ordinary access to participants' private conversations or personal drive.
2. In **User access**, give non-owner ERP accounts the specific areas you want: **Company knowledge**, **Messages**, and/or **Drives**. For the separate employee portal, enable those features in that employee's portal settings. Setting up a company group is separate from enabling a feature. Do not recycle a login for another employee.
3. In **Company knowledge**, the owner can publish searchable plain-text articles and delegate writing and publishing. Readers see published revisions only. History is retained. This is separate from the app's public Setup help and from the private product support manual. Total stored revision content has an 8 MiB budget; make concise manuals.
4. In **Messages**, choose an authorized person or group. Refresh to load new messages. Groups keep past chats for continuing members; joining or rejoining does not grant older messages. Message contents are plain text, not file attachments or public links.
5. In **Drives**, choose your personal or shared group drive, create a folder, and upload or download. This preview limits files to 4 MiB each and 16 MiB total file payloads per server. Removing a member ends future access, not copies already downloaded. Existing files can't be overwritten. FileBirch editing and co-editing are not included yet.
6. For optional server-hosted FTP transfers, configure explicit TLS using [FTPS-SETUP.md](FTPS-SETUP.md). Users copy a single file to or from the fixed approved folder. There is no plain FTP, remote browsing, or background sync.

The whole encrypted Full Suite database backup includes collaboration data, accounts and memberships. The Lite-format portable books export does not. The live database is readable by the server operator and is not end-to-end encrypted. Limit server access; store encrypted backups separately. See the README for the existing whole-database recovery limit.
