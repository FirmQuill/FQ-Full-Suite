# Reviewed migration: exact formats and scope

Work in **Migration workspace** as owner. Staging does not post to your current books. Preview, compare your independent balances/record counts, resolve or acknowledge exceptions, and approve the versioned package before installing it into a fresh workspace. Keep raw source exports private and outside the app folder. No vendor credentials or live service connection are needed.

## QuickBooks Desktop IIF contacts

Select **QuickBooks Desktop contacts** for a staged migration. In QuickBooks Desktop, use the list export documented by Intuit and export a single flat Customer or Vendor list. Use the same source namespace for the same company/export source on repeat imports. The profile accepts a tab-delimited customer list with a `!CUST` header and `CUST` rows, or a vendor list with `!VEND` and `VEND` rows. `NAME` is required. A leading `!HDR` / `HDR` export header pair is optional. Fields outside contact name and type are not posted. Numeric `REFNUM`, when present and stable, is scoped to the source namespace and contact kind. If a stable reference is unavailable, supply a reviewed JSON crosswalk from exact exported names to independently assigned stable IDs. A name is never automatically converted to a stable ID. Check the preview for name conflicts, duplicate records, and whether any source system reused a reference. Track changes to names in your crosswalk rather than assigning a new identity to the same customer.

This is **only a contact-list import**. It does not accept jobs/subcustomers, mixed IIF list/transaction files, QuickBooks Online exports, other QuickBooks formats, balances, addresses, historical invoices, or payments as IIF. Intuit documents Desktop transaction imports but explicitly does not provide native IIF transaction export; there is no transaction IIF support here. IIF typography and exact list markers were checked against Intuit's downloadable sample's contact list sections, extracted solely for verification. Its example files and names are not distributed here.

Sources: [Intuit export/import instructions and limitations](https://quickbooks.intuit.com/learn-support/en-us/help-article/import-export-data-files/export-import-edit-iif-files/L56LT9Z0Q_US_en_US), [Intuit format guide and IIF sample kit](https://quickbooks.intuit.com/learn-support/en-us/help-article/list-management/iif-overview-import-kit-sample-files-headers/L5CZIpJne_US_en_US), and [vendor-provided sample ZIP](https://support.quickbooks.intuit.com/support/pages/executable/iif/invoice.zip).

## Multi-line mapped CSV (not a vendor format)

Choose `invoiceLines` or `billLines`. Map one source row per service line. All lines in the same document must be staged together in one CSV; they share the stable document ID, contact reference, date, and optional document description. Every line in that document needs a distinct durable ID, service name, positive whole quantity, USD unit amount, and separate net amount. Discount is an optional line total. Verify quantity × unit price minus discount against the net amount from the source. If any known line in a document fails validation, none of that document posts. The preview counts outcomes by document and lists the original physical line numbers. Do not infer absent lines; reconcile the source invoice totals before approval. Payments use the original stable **document** ID, not a line ID.

The app imports service records under USD and its fixed chart, not inventory history, tax, non-USD, or attachments. Existing single-service-amount and verified bank CSV mappings continue working. Native invoice/bill exports created by vendor applications have not been verified; do not advertise them.
